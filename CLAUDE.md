## Project Overview

Path of Building Community (PoB) is an offline build planner for Path of Exile, written in Lua (LuaJIT 5.1). The application runs via a custom Windows executable (`runtime/Path of Building.exe`) that embeds a 2D graphics host and Lua runtime.

## Running the Application

**Development mode** (auto-enabled when running from repository):
```bash
./runtime/Path\ of\ Building.exe
```

Dev mode features:
- `F5` — restart in-place
- `Ctrl+~` — toggle console
- `Ctrl+F5` — regenerate `src/Data/ModCache.lua` from `ModParser.lua`
- `ConPrintf()` — output to console
- Hold `Alt` — show debug info in tooltips (internal modifiers, unrecognised stats, node IDs)
- Hold `Ctrl` at launch — force rebuild of mod cache

## Running Tests

Tests use the [Busted](https://lunarmodules.github.io/busted/) framework and require Docker:

```bash
docker-compose up
```

Tests live in `spec/System/`. Test builds live in `spec/TestBuilds/`. Tests run automatically on PRs.

## Branch Policy

**All PRs must target the `dev` branch**, not `master`. `master` is for releases only.

## Architecture

### Entry Point & Core
- `src/Launch.lua` — bootstraps the app, enables dev mode, loads `Main`
- `src/Modules/Main.lua` — top-level: loads game version, common/data/mod/calc/item tools; manages the two program modes (build list vs. build editor)
- `src/Modules/Build.lua` — manages the build screen: all UI controls, build load/save, stat sidebar, calculation output

### Calculation Engine (`src/Modules/Calc*.lua`)
The calc pipeline runs in this order:
1. `CalcSetup.lua` — builds mod databases for player/enemy actors; applies tree nodes, items, flasks, jewels, bandits, pantheons; sets main skill
2. `CalcPerform.lua` — executes the calculation
3. `CalcOffence.lua` — damage/DPS calculations
4. `CalcDefence.lua` — life/ES/evasion/resistance calculations
5. `CalcActiveSkill.lua` — per-skill calculations
6. `CalcBreakdown.lua` — generates the breakdown display
7. `CalcTools.lua` — mod value helpers, skill type validation, gem stat interpolation

### Mod System
- `src/Modules/ModParser.lua` — parses raw mod text into structured mods; generates `src/Data/ModCache.lua` (run with `Ctrl+F5`)
- `src/Data/ModCache.lua` — **auto-generated**; commit this file when mod parsing changes
- `src/Modules/ModTools.lua` — mod creation helpers (`mod()`, `flag()`) and loads ModCache
- `src/Classes/ModDB.lua` — mod database (lookup and storage)

**Mod syntax**: `mod(ModName, ModType, Value, source, modFlags, keywordFlags, extraTags)`
- ModTypes: `"BASE"`, `"INC"`, `"MORE"`, `"OVERRIDE"`, `"FLAG"`, `"MAX"`, `"MIN"`
- All mod text is lowercased before parsing
- Prefer adding new flags/tags over adding to `specialModList`
- Keep old mod wordings for backwards compatibility (legacy items exist in-game)

### Auto-Generated Data (`src/Data/`)
Files with header `-- This file is automatically generated, do not edit!` must not be edited directly. To change them:
1. Modify the scripts in `src/Export/Scripts/`
2. Re-run the exporter via `src/Export/Launch.lua`
3. Commit both the script changes and the regenerated data files

Key data files:
- `src/Data/Global.lua` — `ModFlag`, `KeywordFlag`, `SkillType` enumerations
- `src/Data/ModCache.lua` — parsed mod cache (regenerate with `Ctrl+F5`)

### Skills (`src/Data/Skills/` and `src/Export/Skills/`)
- Template files in `src/Export/Skills/` define skill structure; game data is merged on export
- Skills use `stats`+`levels` tables; stat values are interpolated (types 1=raw, 2=linear, 3=effectiveness)
- Skill-specific logic uses `preFuncs`: `initialFunc`, `preSkillTypeFunc`, `preDamageFunc`, `preDotFunc`

### UI Classes (`src/Classes/`)
UI controls inherit from `Control.lua`. Key tabs:
- `CalcsTab.lua` / `CalcBreakdownControl.lua` — calculations display
- `ItemsTab.lua` / `Item.lua` — item management
- `SkillsTab.lua` — skill gem management
- `ConfigTab.lua` / `src/Modules/ConfigOptions.lua` — configuration options
- `TreeTab.lua` / `PassiveTree.lua` / `PassiveTreeView.lua` — passive tree
